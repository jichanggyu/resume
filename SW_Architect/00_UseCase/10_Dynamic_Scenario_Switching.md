# UC10 – 유연한 시나리오 전환 (Dynamic Scenario Switching)

## 개요

| 항목 | 내용 |
|------|------|
| **유즈케이스 ID** | UC10 |
| **유즈케이스 명** | 유연한 시나리오 전환 |
| **관련 기능 요구사항** | F4-3. 유연한 시나리오 전환 |
| **주 액터** | 운영자 (Web UI 사용자) |
| **목적** | 작업 중에도 상황에 따라 다른 시나리오 또는 작업 흐름으로 전환할 수 있어야 한다. |

---

## 사전 조건

- 시스템에 여러 작업 시나리오가 사전에 정의되어 있어야 한다.
- 로봇은 현재 동작을 일시 중지 또는 종료할 수 있어야 한다.

## 후 조건

- 선택한 시나리오로 작업 흐름이 전환된다.
- 전환된 시나리오에 따라 로봇이 새로운 작업을 수행한다.

---

## 기본 흐름

1. 운영자가 UI에서 현재 작업 흐름을 확인한다.
2. 운영자가 다른 시나리오(A, B, C 등) 중 하나를 선택하고 [전환] 버튼을 누른다.
3. FastAPI는 선택된 시나리오 ID를 ROS2에 전달한다.
4. ROS2는 현재 작업을 안전하게 종료하거나 대기 상태로 전환한 후, 새 시나리오를 시작한다.
5. UI에 변경된 시나리오 및 작업 흐름이 표시된다.

---

## 예외 흐름

- **E1: 시나리오 로드 실패**  
  선택한 시나리오 정의가 존재하지 않거나 파일 오류 발생  
  → UI에 “시나리오 로드 실패” 메시지 표시

- **E2: 전환 중 충돌 위험**  
  동작 도중 전환 시 안전하지 않은 상태가 감지됨  
  → “전환 불가: 현재 작업 완료 후 다시 시도” 메시지 표시

---

## 통신 흐름

| 구간 | 방식 | 내용 |
|------|------|------|
| **Frontend → Backend** | HTTP POST | `/api/robot/scenario/switch` 요청 (시나리오 ID 포함) |
| **Backend → ROS2** | ROS2 Service or Topic | `/robot/scenario`로 전환 요청 |
| **ROS2 → Backend** | 상태 메시지 | 시나리오 변경 결과 전달 |
| **Backend → Frontend** | WebSocket 또는 응답 | 새 시나리오 시작 상태를 UI에 표시 |

---

## 비고

- 시나리오는 JSON, YAML 등으로 정의된 작업 시퀀스일 수 있으며, 유동적 로딩 구조 필요
- 사용자 정의 시나리오 추가 기능도 추후 확장 가능
- ACS와 연동되는 경우 외부 지시 기반 시나리오 전환으로도 활용 가능
