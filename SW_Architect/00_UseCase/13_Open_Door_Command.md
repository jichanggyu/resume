# UC13 – Door Open 명령 (Open Door Command)

## 개요

| 항목 | 내용 |
|------|------|
| **유즈케이스 ID** | UC13 |
| **유즈케이스 명** | Door Open 명령 |
| **관련 기능 요구사항** | F5-3. Door Open |
| **주 액터** | 운영자 (Web UI 사용자) |
| **목적** | 로봇이 장비 또는 구조물의 도어를 열도록 제어한다. |

---

## 사전 조건

- 도어의 위치가 사전에 정의되어 있어야 한다.
- 도어 주변에 로봇 팔이 접근 가능한 상태여야 한다.
- 도어가 이미 열린 상태가 아니어야 한다.

## 후 조건

- 도어가 열리고, 상태가 “열림”으로 UI에 표시된다.
- 로봇은 다음 작업을 위한 준비 상태가 된다.

---

## 기본 흐름

1. 운영자가 Web UI에서 Door Open 명령을 실행하거나, Schedular Node가 Door Open 단계에 진입한다.
2. Command Executor Node는 Door Open 명령을 실행한다.
3. H/W Node 도어를 열기 위한 시퀀스 또는 이동 명령을 전송한다.
4. H/W Node는 로봇팔을 도어 핸들로 이동시킨 후 회전 또는 당김 동작을 수행한다.
5. 도어 열림 확인 센서 또는 시뮬레이션 조건에 따라 성공 여부 판단
6. 결과가 Status Node에 전달된다.
7. FastAPI는 결과 상태를 수신하여 Web UI에 표시한다.

---

## 예외 흐름

- **E1: 도어 이미 열림 상태**  
  센서 또는 내부 상태 기준으로 도어가 열린 상태인 경우  
  → “도어가 이미 열려 있습니다” 메시지 표시

- **E2: 도어 위치 접근 불가**  
  주변 장애물 또는 위치 오류로 인해 도어 위치 접근이 불가능한 경우  
  → “도어 접근 실패” 경고 표시

- **E3: 기구물 충돌 감지**  
  도어 오픈 동작 중 힘 센서 또는 움직임 오류 발생  
  → 동작 중지 및 “충돌 위험” 메시지 표시

---

## 통신 흐름

| 송신자 | 수신자 | 방식 | 메시지 |
|--------|--------|------|--------|
| Schedular Node or UI | Command Executor Node | 내부 명령 or ROS2 Topic | Door Open 명령 |
| Command Executor Node | H/W Node | ROS2 Action or Topic | 도어 열기 동작 실행 |
| H/W Node | Status Node | ROS2 Topic | "도어 열림 성공/실패" 상태 전송 |
| Status Node | FastAPI | ROS2 Topic | `/robot/status` |
| FastAPI | Web UI | WebSocket or 응답 | 결과 상태 표시 |

## 비고

- 도어 오픈은 정해진 궤적 수행이 필요한 복합 동작으로, 모션 계획 포함 필요
- 센서 기반으로 도어가 열렸는지 추가 확인하는 구조 권장
- 일정 시간 내 미완료 시 타임아웃 처리 및 에러 핸들링 필요
