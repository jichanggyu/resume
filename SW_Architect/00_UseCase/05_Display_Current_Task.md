# UC05 – 현재 수행 작업 표시 (Display Current Task)

## 개요

| 항목 | 내용 |
|------|------|
| **유즈케이스 ID** | UC05 |
| **유즈케이스 명** | 현재 수행 작업 표시 |
| **관련 기능 요구사항** | F2-2. 현재 수행 작업 표시 |
| **주 액터** | 운영자 (Web UI 사용자) |
| **목적** | 로봇이 현재 어떤 작업(예: Pick, Place, Door Open 등)을 수행 중인지 실시간으로 확인한다. |

---

## 사전 조건

- ROS2 시스템 내 작업 상태를 정의하고, 현재 작업 상태를 발행하는 구조가 존재해야 한다.
- 웹 UI와 FastAPI가 작업 상태를 수신할 수 있어야 한다.

## 후 조건

- 운영자는 현재 로봇이 수행 중인 작업을 실시간으로 확인할 수 있다.
- 작업명은 UI에 명확한 텍스트 또는 아이콘 형태로 표시된다.

---

## 기본 흐름

1. `Schedular Node` 또는 `Command Executor Node`는 작업 수행 시 현재 작업 ID 또는 명칭을 상태로 발행한다.
2. `Status Node`는 해당 작업 정보를 가공 또는 그대로 relay하여 ROS2 토픽(`/robot/task`)에 publish한다.
3. FastAPI는 이 작업 상태 토픽을 구독하고 Web UI에 전달한다.
4. Web UI는 현재 작업 상태를 텍스트 또는 상태 뱃지로 표시한다.

---

## 예외 흐름

- **E1: 상태 메시지 미수신**  
  작업 상태 메시지를 일정 시간 이상 수신하지 못한 경우  
  → UI에 “작업 상태 없음” 또는 회색 상태 표시

- **E2: 알 수 없는 작업 ID**  
  정의되지 않은 작업 코드가 전달된 경우  
  → UI에 “Unknown Task” 또는 코드 그대로 출력

---

## 통신 흐름

| 송신자 | 수신자 | 방식 | 메시지 |
|--------|--------|------|--------|
| Schedular Node or Command Executor Node | Status Node | 내부 공유 | 현재 작업 ID 또는 이름 전달 |
| Status Node | ROS2 Topic | `/robot/task` |
| FastAPI | Web UI | WebSocket or Polling | 현재 작업 상태 전달 |
| Web UI | UI 컴포넌트 | 시각화 | `"현재 작업: Pick"` 등 텍스트 표시 |

---

## 비고

- 작업 상태는 내부적으로 `작업ID + 상태코드` 구조로 관리 가능 (예: `PICK_START`, `PLACE_DONE`)
- 필요시 작업 시작~완료까지의 타이머 기능도 UI에 표시 가능
- 멀티태스크 환경이라면 서브태스크도 병행 표시 고려
